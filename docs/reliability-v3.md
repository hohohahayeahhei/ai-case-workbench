# 采集可靠性修复（2026-09-19）

本轮修复真实采集中的搜索超时、网页抓取失败、模型输出错误及历史积压。最终版本标记为 `reliability-v3.1`；不调整最近一年、事实证据、独立复审及精选分数门槛。

## 原因与改动

| 原因 | 修复 |
| --- | --- |
| 原搜索 HTTP 最多两次、每次 180 秒，外层 MCP 240 秒提前中止 | 搜索每次默认 90 秒，短退避后最多重试一次，MCP 默认 220 秒；搜索使用低推理强度，复杂站点查询按天轮换最多四个域名 |
| 当前模型网关不支持 `max_tool_calls` | 仅在服务明确报某个可选参数不支持时删除该参数后重试，保留 web_search 工具执行与真实引用校验；普通 400、认证错误不盲目重试 |
| 同主题搜索反复执行；搜索失败拖住整个任务 | 成功搜索引用缓存 6 小时，空结果或错误不缓存；连续两次搜索失败停止剩余搜索，继续处理已有候选；缓存写入失败不丢弃搜索结果 |
| Reader 与直连共用 12 秒超时，备选强制变成 HTTP 并丢失查询参数 | 保留完整原始 HTTPS URL；直连默认 18 秒，Reader 默认 45 秒并使用官方读取超时和可见内容参数；仅瞬时网络错误和 408/429/5xx 做一次退避重试 |
| HTTP 200 的验证码或登录页面进入证据流程 | 识别明显拦截页；Reader 头信息与文章正文分离；维持公网地址、嵌套 Reader 目标、重定向地址校验 |
| 本机 DNS 将 Reader 域名解析到含非公网地址的异常结果，备选实际未执行 | 仅对固定 Reader 服务启用公共 DNS 解析及固定公网 IP 连接，保留 r.jina.ai 的 TLS 域名校验；原文目标仍须通过公网检查，不连接被拒绝的本地地址，不跟随固定服务重定向 |
| 原文域名的本机解析也会波动，直接跳过了公开 Reader | 本机地址被拒绝时，只有公共 DNS 确认原文域名有全为公网的 A 记录才允许转给公开 Reader；私有 IP、localhost、内网域名或公共 DNS 失败仍拒绝，不直接连接异常地址 |
| 部分博客日期藏在作者页脚 | 为 Simon Willison 添加已核实的文章日期页脚解析，要求页脚日期链接匹配当前文章路径；不从相关文章、URL 或收录时间猜日期 |
| JSON 模式只保语法，不保字段/类型；错误后重复相同请求 | 抽取、核验、评分、复审采用严格 JSON Schema，并在本地再次校验；不支持 Schema 的网关只降级输出格式，本地规则保留；格式错误携具体字段错误重生成一次；拒绝和截断不作为有效 JSON |
| 核验能看到发布日期元数据，复审只有正文，反复争议 | 核验、评分和复审使用相同案例证据视图，保留日期及其来源、原始值，排除历史评分输出和重试日志 |
| 新搜索不消费历史；定时脚本仍只处理 5 篇；增加处理预算同时扩大搜索量 | 网页主动搜索默认带入历史，定时预算统一为 12 篇；发现量与处理预算分离；可处理积压达到预算两倍时，仅保留少量新搜索并暂缓自动 RSS 扩张，优先消费历史 |
| 旧错误已耗尽重试，修复后仍永远跳过 | 对本轮可修复的技术失败按处理版本重新开启一次有限重试预算，保留历史尝试记录；之后仍最多 3 轮，保留冷却及耗尽状态 |
| 模型整体故障时逐条消耗所有候选重试机会 | 连续两篇模型服务错误后暂停本轮，其余尚未处理案例不增加尝试次数 |
| 直连 403 后 Reader 超时，也被当成永久拒绝访问 | 按最后实际失败路径分类，瞬时 Reader 超时使用短冷却，保留完整路径错误说明 |
| UI 混淆新增、历史、待处理与审核失败 | 显示新增与带入历史数量、处理预算、积压优先策略及停止原因；仍有待处理队列时任务标记部分完成 |

## 官方资料与适用边界

- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)：JSON Schema 约束字段与类型，但不能替代事实核验；需要处理拒绝及不完整输出。
- [OpenAI Web Search](https://developers.openai.com/api/docs/guides/tools-web-search)：降低推理强度以缩短搜索响应，保留工具引用；兼容网关支持程度须实测。
- [Jina Reader](https://github.com/jina-ai/reader)：完整 URL 前缀、`X-Timeout` 和 `X-Respond-Timing`。Reader 只读取可公开取得的内容，不绕过账户、付费墙或验证码。
- [MCP Python SDK migration](https://py.sdk.modelcontextprotocol.io/migration/)：当前 SDK 调用超时按秒配置；外层超时需覆盖内层网络重试。
- [urllib3 Retry](https://urllib3.readthedocs.io/en/stable/reference/urllib3.util.html)：参考瞬时错误分类、有限退避及 Retry-After；本项目沿用 urllib.request，无新增依赖。
- [Google Public DNS JSON API](https://developers.google.com/speed/public-dns/docs/doh/json)：对固定 Reader 域名使用 A 记录查询并验证响应状态与地址，随后只向验证过的公网 IP 建立 TLS 连接。

HTTP 超时是 socket/请求尝试预算，并非严格整轮完成时限。每篇依次经历多个 Agent，必要时有一次证据或评分修正，处理十余篇仍可能耗时数分钟。外部站点永久关闭、付费或缺少日期不保证自动解决，应保留真实状态。

## 使用与恢复

网页“联网找案例”自动同时消费历史队列；“重试待处理”不执行新搜索。对较多积压会显示“积压优先”。定时任务仍每天运行一次，不增加新的后台定时器。

仅重试指定记录（不搜索新文章）：

```bash
.venv/bin/python scripts/run_collection.py --source-mode live --retry-pending --no-search --case-id web-实际ID --max-results 3
```

`--case-id` 可重复，必须搭配重试且不能同时启用搜索、目录或订阅；同样遵守冷却和次数上限。常规恢复不删除队列，不将失败记录直接改成已通过。

安装前已备份代码和完整数据库，数据库 integrity_check 为 ok：`data/runtime/backups/reliability-v3-20260919-234735/`；DNS 追补保存在其 `reader-followup/`。
