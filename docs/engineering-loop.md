# 自检与迭代闭环

这个项目每次增加功能后都执行以下循环：

1. **运行**：启动模拟成功、冲突和未知结果三种场景。
2. **验证**：检查状态、案例数量、分发任务和回执是否符合产品规则。
3. **找异常**：重点检查刷新恢复、重复运行、人工拒绝、部分写入和外部结果未知。
4. **修复**：先修复状态机或数据模型，再修改界面表现。
5. **回归**：运行全部 Python 测试和前端生产构建。
6. **记录**：把发现的问题和对应测试留在提交说明或文档中。

## 一键执行

```bash
.venv/bin/python scripts/self_check.py
```

当前自检覆盖：

- LangGraph 审核暂停与恢复
- 审核拒绝后的终态
- 页面刷新后从 SQLite 恢复待审核状态
- 成功、同步冲突、发布未知三种场景
- MCP Server 工具目录
- 官方 MCP SDK 的 stdio 初始化、Tools、Resources、Prompts 和幂等调用
- 模型故意输出错误结论和编造内容时，确定性护栏仍能阻断
- 同步冲突和发布未知结果只做局部恢复，不重跑前置 Agent
- 评测中心能比较直接相信模型与增加护栏后的结果
- 前端构建
- Catalog DB 离线快照保持待评分，实际模型评审才可产生质量分
- RSS/Atom 候选保持 `needs_extraction`，不会被自动编造成案例

启动脚本：

```bash
bash scripts/start_demo.sh
```

该脚本启动本地 API 和 Vite 前端，先检查 `/api/readyz`，退出时清理两个子进程。

新版额外验证独立复审、一次修正上限、无评分时为空值、原文引文定位、输入变化使批准失效，以及数据库/查询/导出同口径。新增测试使用合成评审输出，只验证工程行为，不是内容质量标注集。
