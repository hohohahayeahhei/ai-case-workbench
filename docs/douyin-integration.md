# 抖音来源接入与能力边界

本次实现是工作台的本地来源适配器。浏览器观察、证据处理和模型审核是不同阶段；HTTP 标题读取、关键词命中、单元测试通过均不代表完成真实视频理解。实际线上采集验收另见本次验收记录；本文描述代码行为，不把受控样本计入真实成功率。

## 现有入口与职责

现有每日 `CollectionPipeline.run(source_mode='live')` 会读取已达到 `ready` 的作品，单轮视频最多 `min(3, ceil(max_results / 3))` 条，与网页共用 `max_results` 总预算。已有文章积压不能无限推迟这批视频；未取得证据、登录和验证限制等状态不会占用模型预算。关键词、作者和抖音分享链接进入本地队列；队列需要允许的本地真实浏览器读取或用户导入，当前程序不会在后台操纵浏览器。

网页搜索或 RSS 发现抖音链接时直接交给 `DouyinStore.import_link`，不会用通用 HTTP 抓取器或第三方解析站把标题伪造成正文。非抖音来源继续现有流程。没有新建或改变独立的 Codex 定时任务、日报分发或腾讯文档设置。

| 部件 | 实际职责 |
| --- | --- |
| 本地浏览器 / 操作者 | 打开公开作品或搜索、识别登录与限制、观察日期与作者、记录时间证据 |
| `douyin_source.py` | URL 归一化、作品和任务队列、SQLite 记录、证据校验、状态及媒体容量管理 |
| `douyin_media.py` | 允许导入的本地素材检测及可用本地转写工具适配；不存在工具时报告失败 |
| `case-douyin/SKILL.md` | 搜索题材、排除条件、时间证据、结果归因与不确定性规则 |
| MCP `douyin_search/read/status` | 只读本地记录、状态和浏览器操作计划，不实际运行浏览器、不写库 |
| 既有模型职责 | 同一现有模型配置分别执行抽取、核验、评分、独立复审 |
| 采集程序 / curator | 总额度、去重、模型熔断与重试、本地入库 |

这些部件没有增加独立模型或虚构的新 Agent。抖音 Skill 仅在抖音作品的 extract/verify/score/review 调用中实际加载，发现规则也可从 MCP `policy://douyin` 读取；其版本哈希出现在运行记录中。普通文章继续使用原指令及原有批准指纹，不因新增抖音规则被降为待评分。MCP 的 `fetch_page` 对抖音返回 `awaiting_browser`，避免其他调用方绕过证据入口。

## 从线索到可审核证据

1. 粘贴分享文本、短链或作品链接，保存规范链接、作品 ID、采集时间和查询词。短链只有浏览器确认实际作品后才归并，程序不自行调用私有接口。
2. 观察公开页面，保存标题、作者、页面发布日期及依据、观测时间。互动量只在真实可见时录入，附观测时间；不参与质量分。未知日期、未来日期、最近一年以外分别记录。
3. 在平台允许的方式下取得素材，或由用户本地导入。没有素材就保留线索与明确原因，不编造转写。机器转写/OCR 与人工画面核对分别标记。
4. 每段证据包含 `kind`、`role`、`text`、`start_seconds`、`end_seconds`、`source_url`，并可带原文、语言、不确定性和机器识别标志。图文使用页码明确标记，不能把图序误称为实际音频时间。
5. 只有有效发布日期、问题或工作流证据、至少两段时间证据，以及结果画面或外部印证都存在时，才能进入 `ready`。未核实的机器画面识别不能独立满足结果门槛。
6. 程序将完整证据段落生成原始文档，保留时间位置和归因。再运行既有抽取、核验、评分与复审。抽取的三类引文均需绑定时间证据，结果引文必须绑定相应 `role=outcome` 的可核验画面或外部印证；其他画面不能替口播数字背书。

70 分入选、85 分精选及 case-quality-v4 的各维度权重不变。作者说“效率十倍”只能是作者主张；可见成果可以支持完成了何种任务，不能自动支持未测量的效率、准确率或商业收益。入选为 0 也是有效验收结果。

## 状态、续跑和审计

| 状态 | 含义与后续 |
| --- | --- |
| `awaiting_browser` | 等待允许的本地浏览器读取；短链可能尚未归并 |
| `waiting_login` / `manual_verification` / `rate_limited` | 来源暂停，由用户完成登录或验证、限制解除后再恢复；不破解、不轮换账号或代理 |
| `unavailable` | 作品删除、失效或无法访问；保留观察原因 |
| `media_unavailable` | 取得页面元数据但尚无允许取得的素材/时间证据 |
| `transcription_failed` | 本地转写未成功；保留失败原因，不用标题替代正文 |
| `date_unknown` / `future` / `outdated` | 日期无法确认、未来日期或超出最近一年 |
| `evidence_insufficient` | 无实际结果证据或抽取结果只得到口述支持 |
| `network_error` | 网络失败，有限重试并保留进度 |
| `ready` | 最低证据门槛通过，等待原审核流水线 |
| `processed` | 已经移交并完成该轮审核；最终结果见 `metadata.collection_status` 与案例记录，不等于入选 |

模型失败沿用 `source_items` 的冷却时间、最多三次尝试和连续两篇故障熔断。已完成作品不重复入库；相同观察/证据重放不触发模型。新增证据、核实标记或发布日期变化产生新证据版本，才重开原案例审核并清除旧批准。视频自己的读取/模型错误单独记录，不阻止其他可用来源。

运行事件包含阶段、起止时间、匹配阶段耗时、失败原因和作品 ID；视频来源表还保存浏览器观察、媒体、证据与状态事件。原始文档保存在现有 `raw_documents`，结构化案例保存在 `source_items`，视频事实可由 `douyin_item_id` 追溯。

## 素材、安全和本地限制

媒体单独存放于运行数据目录的 `douyin_media`，当前默认总容量 2 GiB、单次上传 200 MiB、处理时长 30 分钟。按显式保留天数或容量策略清理素材；结构化证据和审核记录继续保留。清理后页面应回到原作品链接并提示时间，不能宣称本地仍可播放。

浏览器登录状态只由本地浏览器维护；适配器不接收或保存 Cookie、Authorization 头、任意文件路径。URL 校验限制公开 HTTP(S)，抖音入口仅允许识别的域名与链接形态；媒体通过上传字节和服务器内部标识访问。页面文字、评论、转写及画面内容均为不可信证据，不能成为系统执行指令。

本机没有配置可用转写运行时/模型时会明确报 `transcription_failed`，不会将音频发往未经验证的文本模型网关。浏览器登录、访问限制和素材取得仍是独立于代码测试的现实依赖。

## 验证与上游代码

新增受控测试覆盖：抖音搜索命中路由、重复执行不入库/不重评、真实 SQLite 适配器到既有四模型阶段的契约、口述结果拦截、日期缺失拦截、模型故障冷却、小批量总预算、来源失败隔离、MCP 只读且不创建浏览器任务。受控模型返回值与受控证据只验证工程边界，不算真实案例或真实转写成功。

本实现为项目内独立编写的适配器，没有复制或引入 MediaCrawler、douyin-downloader、Douyin_TikTok_Download_API 的代码，也不继承其可能变化的接口可用性。此前调研项目仅用于架构比较。若另行安装本地转写工具和模型，应分别核对该工具及模型许可证；本补丁不捆绑模型权重。
