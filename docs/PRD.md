# MVP 产品说明

## 1. 产品定位

AI 案例情报工作台帮助 AI 产品经理持续发现、核验和整理真实 AI 产品案例，并在确认后同步到团队知识库和消息渠道。

产品的核心价值不是自动写一篇文章，而是让用户能够回答：

- 今天发现了什么？
- 哪些案例有足够证据？
- 哪些内容被淘汰，为什么？
- 日报、知识库和消息发布分别进行到哪一步？
- 失败后能否从局部恢复？

## 2. 目标用户

- AI 产品经理：发现竞品、行业和落地案例
- 产品负责人：审核案例真实性和可借鉴性
- 内容运营：确认日报并发布给团队

## 3. MVP 用户流程

1. 用户配置关注主题、来源偏好和日报数量。
2. 用户点击“开始运行”或等待定时任务。
3. 研究 Agent 按来源检索并保存原文证据。
4. 核验 Agent 检查真实性、重复和结论支持关系。
5. 编辑 Agent 只使用通过核验的内容生成日报草稿。
6. 系统执行程序校验并冻结内容版本。
7. 用户在审核节点批准或驳回。
8. 确定性同步执行器写入模拟知识库并回读比较。
9. 确定性发布执行器发送冻结文案并保存回执。

## 4. MVP 页面

### 今日工作台

显示运行状态、候选数量、通过数量、淘汰原因、知识库同步状态、发布状态和待处理事项。

### 案例审核

显示原始标题、原文链接、问题/方法/结果、原文证据、核验结论、草稿和差异。

### 运行详情

按时间线显示 Agent 节点、MCP 工具调用、耗时、输入输出摘要、失败原因和重试。

### MCP 与连接器

显示 MCP Server、工具 Schema、权限、调用记录和模拟/真实模式。

## 5. MVP 验收标准

- 能用本地 Fixture 跑通一次完整闭环。
- 至少一个案例通过，至少一个案例被淘汰，并展示淘汰原因。
- 日报生成后能够冻结版本，后续流程只能消费冻结版本。
- 同步失败时只重试失败任务，不重复写入成功任务。
- 回读内容不一致时进入冲突状态，不能自动覆盖。
- 发布超时时显示 `unknown`，先查询回执。
- 所有 Agent 和 MCP 调用都能在运行详情页定位。

## 6. 明确不做

- 不在公开 Demo 中使用真实企业账号。
- 不读取或上传原项目中的企业私密信息。
- 不让模型直接改写已冻结内容。
- 不为了展示而堆叠大量 Agent。
- 不把未测量的效果写成产品收益。
