## 本地工程验证

完整自查通过 240 项 unittest、官方 MCP 协议检查、离线采集 smoke 和前端构建；随后新增的 3 项 API 回归也通过（API 组共 15 项）。这些数量为工程检查结果，不是线上内容质量评测。

- 实际 SQLite、FastAPI 和 React 页面完成链接录入、重复导入、作者/页面日期保存、时间证据录入、状态变化和发现任务展示的联调。测试用独立临时数据库；受控作品和文字均不进入正式案例库。
- 核心测试涵盖口述主张、可见演示、图文定位、重复作品、不可用/验证状态、日期缺失、素材路径与容量、并发写入、机器证据核实标志与有限重试。
- 原抽取、核验、评分、独立复审流程用受控证据和受控模型完成端到端入库验证；重复执行不再调用模型，新证据重新审核。结果引文不绑定画面/外部结果时阻止入选。
- 三个抖音 MCP 工具经官方 SDK stdio 实际往返验证，只读本地记录及浏览器操作计划，不把工具调用描述为执行了在线搜索。
- 修复了来源 Skill 全局附加会使历史网页评分失效的问题，增加普通文章指纹兼容测试。修复超过二十条待审核队列时指定作品未被处理的问题。
- 本机缺少 ffmpeg、ffprobe、whisper.cpp/faster-whisper 和模型。受控静音音频在真实本地处理路径返回 `transcription_failed`、证据为零、素材保留。尚无真实识别质量结论；没有自动 OCR 或画面理解引擎。
- GitHub 发布准备中发现 Python 多目录自动打包失败，改为显式只打包 backend，并补充测试依赖。wheel 构建通过。启动应用仍需完整仓库中的 Skill、来源目录及前端，推荐按 README 从克隆目录可编辑安装。

## 继续验收所需

1. 用户在当前抖音扫码页完成登录/平台验证，然后在工作台恢复来源。
2. 正常访问并分别检查口播、屏幕演示、图文等五条小样本，记录可见完整发布日期、作者和规范作品链接。
3. 取得平台允许下载或用户有权导入的素材。配置本地转写工具及模型后，核对中文转写和关键画面；无法取得素材的条目继续保留明确失败状态。
4. 使用原 70/85 分规则和四阶段审核，统计真实候选、可读、可转写、可审核、入选数量与耗时；入选为零也如实记录。

没有复制或安装 MediaCrawler、douyin-downloader、Douyin_TikTok_Download_API 的代码；它们仅为先前架构调研资料。未新增独立定时任务或修改另一套每日案例日报与分发设置。
