# 案例质量评分 v4

当前规则为 `case-quality-v4`。这是本项目面向「AI 解决实际工作和生活问题」的辅助筛选标准，不声称复刻 AIHOT 的内部公式。精确的维度、0—4档行为描述在 [评分规则](../skills/case-score/references/rubric.md)，由代码加载到评分与复审两次模型调用中；Skill及引用规则的哈希会随评审结果保存。

## AIHOT 公开了什么

2026-09-14—15 查询其官网、API说明、GitHub固定提交 `48e8ba527f0be55f77772debb979c92f06acf5c0`，并逐份读取 AIHOT SKILL.md 的28个公开历史版本：未找到完整权重、提示词或服务端评分实现。历史版本只说明分数0—100、可为空，最新版本要求保持服务端顺序。

可确认的原则：

- [官方说明](https://aihot.news/llms.txt)：LLM 生成摘要并打分精选。
- [官方更新日志](https://aihot.news/changelog)：8月30日强调内容价值、减少标签与表达干扰；7月13日强调一手材料及重复报道归并；6月12日减少公关营销等内容。
- [Skill](https://github.com/KKKKhazix/khazix-skills/blob/48e8ba527f0be55f77772debb979c92f06acf5c0/aihot/SKILL.md)：分数、精选状态、热榜排名是不同字段，空值不可编造；关键词无精选时可以有标记地查询全部公开条目。

这些原则并未证明 AIHOT 使用我们的70/85阈值。官网精选可见60多分条目，不能从少量观察反推算法。该站模型榜的「共识分」也不是文章评分。

## 本项目怎么判断

1. 抽取 Agent 为问题、方法、结果附原文连续引文；程序检查引文位置和数字，允许一次修正。
2. 核验 Agent 另读原文，检查主体、因果、单位、实际任务和可观察结果。核验通过指原文支持自述，不代表独立复现。
3. 评分 Agent 按六维给0—4档、理由、引文及缺口：来源15、问题15、方法25、结果25、可复用15、学习价值5。
4. 独立复审调用重新读取原文和评分提案，逐维判断档位是否有依据，并检查事实、归因、清晰度与读者价值。当前使用同一个配置模型的独立上下文调用，不声称是不同模型交叉验证。
5. 若有错误，带明确反馈返回评分 Agent 重读原文，最多修正一次；仍不通过或模型不可用就保留 `needs_scoring`，分数为 `null`。
6. 程序计算 Σ(档位÷4×权重)，最后四舍五入。70起入选、85起重点推荐；问题、方法、结果均至少2档。事实门槛无法被总分抵消。

客户访谈、个人自述均按相同规则；官网不自动满分。单篇单来源可追溯性最高3档。更多字、更长英文、Agent/MCP关键词、单独一个百分数均不自动加分；明确局限也不自动扣分。没有数字但有具体产物可以满足结果2档。

HKR来自 [khazix-writer](https://github.com/KKKKhazix/khazix-skills/blob/48e8ba527f0be55f77772debb979c92f06acf5c0/khazix-writer/SKILL.md)，本项目仅借鉴知识量与读者相关性；吸睛不覆盖证据质量。它不是已证实的AIHOT公式。

## 存储、重评与阅读

- 每条存储输入指纹、正文哈希、模型标识、规则版本、每次评分和复审反馈。摘要、来源、核验、局限或评分Skill改变后，旧批准自动失效。
- 启动时用 `reconcile_scores` 对齐旧卡片和状态；旧版本保存在 `score_history`，过期评分转待评分。此步骤不调用模型。
- 执行 `.venv/bin/python scripts/regrade_catalog.py --limit 20` 从已缓存原文重新评分。脚本与采集共用锁、先备份SQLite、逐条保存、输出本次报告及本地导出；中断后可继续处理未完成项。
- 所有查询及导出使用同一 `score_case`；精选只读审核有效的案例。全部案例页面可展开评分依据及缺口；缺口是待补信息清单，不声称已经从第二来源自动补齐。
- `/api/v1/hot` 为兼容入口，返回「近期精选」并明确 `heat_available=false`。没有真实热度算法。
- 精选同步为「完整快照＋变化时要求重新拉取」，没有逐条增量日志，不把空changes当作永远没变化。

本轮工程测试证明规则、状态与接口行为，未做人工标签集校准或评审一致性研究；不能宣称评分准确率。
